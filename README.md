# Учебные проекты ИМСИТ

Два самостоятельных приложения на Java 21 и Spring Boot 4.1.1: чат-бот для хранения сообщений в сеансах и сервис поиска свободных номеров гостиницы. Проекты разработаны в рамках дисциплины «Разработка и стандартизация программного обеспечения».

## Структура

```text
pom.xml          — объединяет модули Maven
mvnw / mvnw.cmd  — Maven Wrapper
chatbot/         — сеансы и сообщения, хранение в памяти
hotel/           — поиск номеров, Spring Data JPA и H2
postman/         — коллекции для проверки обоих API
```

Архитектура разделена на контроллеры, сервисы, модели и репозитории. Чат-бот реализован без Kernel. Модули запускаются отдельно и не обращаются друг к другу.

## Сборка и запуск

Установите JDK 21 и настройте `JAVA_HOME`. Отдельная установка Maven не требуется. При первой сборке нужен доступ к сети для загрузки Maven и зависимостей. В IntelliJ IDEA откройте корневой `pom.xml` как Maven-проект и выберите JDK 21.

Команды выполняются из корня репозитория в PowerShell:

```powershell
# Сборка обоих приложений, тесты и проверка покрытия гостиницы
.\mvnw.cmd clean verify

# Тесты отдельного модуля
.\mvnw.cmd -pl chatbot test
.\mvnw.cmd -pl hotel verify

# Запуск чат-бота
.\mvnw.cmd -pl chatbot spring-boot:run

# Запуск гостиницы
.\mvnw.cmd -pl hotel spring-boot:run
```

На Linux/macOS вместо `.\mvnw.cmd` используйте `./mvnw`.

По умолчанию оба приложения используют `http://localhost:8080`. Для одновременной работы запустите гостиницу в отдельном терминале на порту 8081:

```powershell
.\mvnw.cmd -pl hotel spring-boot:run "-Dspring-boot.run.arguments=--server.port=8081"
```

После сборки приложения можно запустить из JAR:

```powershell
java -jar chatbot/target/chatbot-0.0.1-SNAPSHOT.jar
java -jar hotel/target/hotel-0.0.1-SNAPSHOT.jar --server.port=8081
```

## Чат-бот

Приложение создаёт сеансы, сохраняет сообщения и возвращает их по номеру. Идентификатор сеанса — UUID. Нумерация сообщений начинается с единицы отдельно для каждого сеанса. Данные хранятся в памяти и теряются после перезапуска. Генерация ответов с помощью ИИ не реализована.

| Метод | Путь | Операция | Успешный статус |
| --- | --- | --- | --- |
| POST | `/api/sessions` | Создать сеанс | 201 |
| GET | `/api/sessions/{sessionId}` | Получить состояние сеанса | 200 |
| POST | `/api/sessions/{sessionId}/messages` | Сохранить сообщение | 201 |
| GET | `/api/sessions/{sessionId}/messages/{number}` | Получить сообщение | 200 |
| DELETE | `/api/sessions/{sessionId}` | Завершить сеанс | 204 |

Для сохранения сообщения передайте `Content-Type: application/json` и тело:

```json
{"text": "Привет, бот!"}
```

Ошибки возвращаются в JSON с полями `code` и `message`: 400 — некорректный запрос, 404 — сеанс или сообщение не найдено, 409 — достигнут лимит сообщений, 415 — неподдерживаемый формат тела запроса. Повторное удаление сеанса возвращает 204.

Настройки находятся в `chatbot/src/main/resources/application.properties`:

| Параметр | Значение по умолчанию |
| --- | --- |
| `chatbot.session-timeout` | `15m` — срок неактивности сеанса |
| `chatbot.cleanup-interval` | `60000` — интервал очистки в миллисекундах |
| `chatbot.max-messages` | `1000` — сообщений в сеансе |
| `chatbot.max-message-length` | `4096` — символов Unicode в сообщении |

## Гостиница

Запрос `GET /bookings?money=400` возвращает свободные номера стоимостью не выше указанного бюджета, отсортированные по цене. В ответе передаются номер комнаты, цена и категория.

Начальные данные из `hotel/src/main/resources/data.sql` содержат 25 номеров:

| Категория | Цена | Количество |
| --- | ---: | ---: |
| ECONOMY | 200 | 10 |
| STANDARD | 400 | 10 |
| PREMIUM | 600 | 5 |

Если подходящих номеров нет, API возвращает 404 с сообщением «Таких номеров нет». Отсутствующий или некорректный параметр `money` приводит к 400; неподдерживаемый POST — к 405.

Поиск не сохраняет клиента, не списывает деньги и не занимает номер. Бронирование, заселение и выселение не реализованы. База H2 и таблицы инициализируются при запуске приложения.

## Тестирование и покрытие

Модульные тесты проверяют сервисы, преобразование данных и обработку запросов с подменой зависимостей. Для чат-бота дополнительно проверяются изоляция сеансов, тайм-ауты, лимиты и нумерация при одновременной записи. Интеграционные тесты проверяют API с контекстом Spring, а для гостиницы — также репозиторий и базу H2.

При проверке 09.10.2026 успешно выполнены 53 теста: 12 для чат-бота и 41 для гостиницы. Ошибок и пропусков нет.

JaCoCo настроен для гостиничного модуля. Команда `verify` формирует отчёт `hotel/target/site/jacoco/index.html` и проверяет минимальное покрытие 80% по строкам, методам и ветвям.

| Метрика гостиницы | Покрытие полного набора тестов |
| --- | ---: |
| Строки | 92,59% (25/27) |
| Методы | 91,67% (11/12) |
| Ветви | 100% (2/2) |

Для чат-бота процент покрытия не измеряется: JaCoCo в модуле не настроен.

## Postman

Импортируйте нужную коллекцию и выполните её через Collection Runner после запуска соответствующего приложения:

- `postman/Chatbot.postman_collection.json` — 8 запросов для проверки сеанса, сообщений и ошибок; идентификатор сеанса сохраняется автоматически.
- `postman/Hotel.postman_collection.json` — 16 запросов и 32 проверки бюджета, выдачи и ошибок.
- `postman/Local.postman_environment.json` — окружение гостиницы с адресом `http://localhost:8080`. Для запуска на порту 8081 измените `baseUrl`.

Коллекция гостиницы рассчитана на исходные данные из `data.sql`. Подготовка коллекций не означает, что они были выполнены в Postman.

Дополнительные сведения о сценариях проверки: [postman/README.md](postman/README.md).
