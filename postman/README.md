# Проверки гостиницы

## Postman

1. Установите JDK 17 или новее и задайте JAVA_HOME.
2. В корне проекта запустите приложение: `./mvnw.cmd spring-boot:run` (Windows) или `./mvnw spring-boot:run` (Linux/macOS).
3. Импортируйте `Hotel.postman_collection.json` и `Local.postman_environment.json` в Postman.
4. Выберите окружение **Hotel local**, при необходимости измените `baseUrl` (по умолчанию `http://localhost:8080`).
5. Запустите всю коллекцию через Collection Runner.

Коллекция содержит 16 запросов и 32 проверки. Она рассчитана на исходные данные из data.sql: 10 номеров по 200 рублей, 10 по 400 и 5 по 600. Запускайте на отдельном экземпляре приложения с исходной базой. При старте текущая конфигурация приложения пересоздаёт таблицы.

Проверяются границы 199/200, 399/400, 599/600, максимальный int, отрицательные бюджеты, нулевой бюджет, отсутствие параметра, пустое значение, строка, дробь, переполнение int и неподдерживаемый POST. Для успешных ответов проверяются JSON, точное количество и номера комнат, цены, категории, сортировка и доступность по бюджету. Порядок внутри одной цены не фиксируется.

Для запуска из командной строки при установленном Node.js/npm:

```powershell
npx --yes newman run postman/Hotel.postman_collection.json -e postman/Local.postman_environment.json
```

## Юнит-тесты и покрытие

В корне проекта:

```powershell
./mvnw.cmd clean verify
```

JaCoCo формирует HTML-отчёт в `target/site/jacoco/index.html` и XML в `target/site/jacoco/jacoco.xml`. На фазе verify сборка завершается ошибкой, если покрытие строк, методов или ветвей всего приложения ниже 80%. Исключений классов из расчёта нет; сгенерированный Lombok-код фильтруется самим JaCoCo.

Только юнит-тесты (включая изолированные тесты MVC с mock-сервисом):

```powershell
./mvnw.cmd clean verify "-Dtest=HotelServiceTest,HotelControllerTest,RoomMapperTest,ClientDtoTest"
```

- HotelServiceTest: передача бюджета в репозиторий, преобразование нескольких результатов, отсутствие подходящих комнат, отсутствие записи клиентов и заселения при поиске.
- HotelControllerTest: JSON-контракт, передача бюджета, HTTP 404/400/405.
- RoomMapperTest: перенос полей для всех категорий.
- ClientDtoTest: сохранение бюджета, включая границы int.
- RoomRepositoryTest: дополнительные интеграционные тесты на H2 — исходные данные, фильтрация по бюджету, сортировка, исключение занятых комнат, исчерпание доступной категории. Изменения откатываются после каждого теста.
- ImsitDevelopAndSertificationApplicationTests: загрузка контекста приложения.

## Ограничения реализации

Текущая программа реализует только поиск через `GET /bookings?money=...`. Поиск не занимает номер, не списывает деньги и не сохраняет клиента. Поэтому коллекция не проверяет заселение, выселение или защиту от двойного бронирования при конкурентных запросах: такой функциональности в проекте пока нет. Полностью занятую категорию проверяет интеграционный тест, поскольку API изменения занятости отсутствует.

Для запуска исправлены исходные проблемы: файл ErrorHander.java содержал публичный класс с другим именем и недопустимой аннотацией; теперь ErrorHandler.java преобразует NotFoundException в HTTP 404 с JSON `{"message":"Таких номеров нет"}`. Также исправлена обработка отсутствующей ссылки Target в Windows Maven Wrapper.
